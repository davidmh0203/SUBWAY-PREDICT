## S03. 기획 의도 — 문제 정의

**제목**: 왜 “빠른 길”만으로는 부족한가

- 출퇴근·등하교 시간에 지하철 혼잡은 이동 만족도를 크게 좌우한다.
- 기존 길찾기는 **최단시간·최소환승** 중심 → “덜 붐비는 길”을 고르기 어렵다.
- 혼잡 정보는 **실시간·열차별**에 편중되거나, **경로 옵션 간 비교**가 약하다.
- (자리) 관련 기사·통계 스크랩 1~2개 삽입

**한 줄**: 출발 전에, 경로 단위로 혼잡을 비교할 수 있어야 한다.

## S05. 벤치마킹 ① — 비교 대상

발표용 3개:

1. **지하철종결자** — 실시간/통계 혼잡, 칸별 색, 길안내
2. **카카오맵** — 길찾기 + 일부 열차 혼잡·량별 시각화
3. **네이버지도** — 익숙한 대중교통 경로, **열차 혼잡 부재**

(참고만) 또타/사이버스테이션 — 노선도·열차정보 강점

## S06. 벤치마킹 ② — 장·단점 (사용성)

| 서비스 | 장점 | 단점 |
|--------|------|------|
| 종결자 | 칸별·노선 혼잡 정보량 | 혼잡까지 **화면 이동 多**. 경로와 혼잡이 **분리** |
| 카카오맵 | 길찾기 안 열차 혼잡 일부 | **현재 열차** 중심, 미래 시각·경로 간 **쾌적 비교** 약함 |
| 네이버지도 | 경로·시간 UX | **혼잡도 없음** |

→ 디자인 비판이 아니라 **정보 도달 경로·의사결정 지원** 관점.

## S07. 개선점 · 차별점 → 목표

**개선·차별**

1. 경로 목록에서 **최단 vs 쾌적** 동시 비교  
2. **역사 혼잡**과 **열차(편성) 혼잡** 분리 표기  
3. 출발 **시각 기준 예측**  
4. 특일·날씨·행사·운행알림 → **정체 예보**  
5. 칸별은 데이터/모델 부담으로 **1차 제외** (솔직한 범위)

**목표**  
출발역·도착역·출발 시각 입력 → 복수 경로의 예측 혼잡 비교 → 상황에 맞는 이동 선택.

## S09. 페르소나 (3명)

→ 공통: “출발 전, 경로 단위 혼잡 비교” (최초 목표 유지)

## S10. 사용자 시나리오 (대표 1)

1. 서준이 출근 전 여유로를 연다.  
2. 홈에서 정체 예보를 스와이프해 행사 영향을 확인한다.  
3. 출발·도착·08:20을 넣고 검색한다.  
4. 결과에서 **최단 28분(혼잡)** vs **쾌적 32분(보통)** 을 비교한다.  
5. 쾌적 경로 상세에서 구간 스트립·열차 혼잡을 보고 출발한다.  
6. (선택) ★로 즐겨찾기 → 다음날 같은 시각 재조회.

## S23. 자체평가

**잘한 점**

- 벤치 단점 → 차별점 → 구현까지 스토리가 일관됨
- 최단/쾌적 비교, 역사·열차 혼잡 분리 등 **기능적 개선**에 집중
- FE 데모 + BE/ML 파이프라인을 짧은 기간에 연결

**아쉬운 점**

- 칸별 혼잡·상세 미니맵은 데이터/일정으로 제외·미연결
- Vercel은 FE-only → 풀기능 시연은 로컬 API 필요
- 일부 노선·구간 데이터 공백 (서울 관할 중심)
- (팀 확인) 모델 지표를 발표에 더 명확히 제시할 여지
