## 2. 주제 선정 · 기획 의도

### 2.1 후보에서 확정까지

| 후보 | 기각/채택 요지 |
|------|----------------|
| 응급실 과밀도 | 실시간 API는 있으나 **과거 히스토리 부족** → 2주 학습 데이터 확보 곤란 |
| 밤길 안전 경로 | **실제 범죄 라벨 비공개**, 공간 JOIN 난이도↑ → 지수 설계에 그칠 위험 |
| **지하철 혼잡도** | 승하차·혼잡 공공데이터 안정, 예측·경로 결합 가능 → **채택** |

### 2.2 문제 정의

- 기존 길찾기는 **최단시간·최소환승** 중심이라 “덜 붐비는 길”을 고르기 어렵다.
- 혼잡 정보는 **실시간·열차별**에 편중되거나, 경로 옵션 **간 비교**가 약하다.
- 역사(플랫폼) 혼잡과 열차(편성) 혼잡이 섞여 보이면, “지금 역이 붐비는지 / 탈 열차가 붐비는지”가 불명확하다.

### 2.3 서비스 목표 (한 줄)

> 출발역·도착역·출발 시각을 넣으면 **복수 경로의 예측 혼잡도**를 비교해, **최단**과 **쾌적** 중 상황에 맞는 이동을 고르게 한다.

### 2.4 범위

| 포함 | 제외 |
|------|------|
| 서울교통공사 관할·데이터 있는 노선 중심 노선도 | 칸별(량별) 혼잡도 UI·모델 |
| 역사 혼잡 예측 + 열차(편성) 혼잡 표현 | 실시간 열차 위치 추적 |
| ODsay 경로 + LightGBM(로컬 API) | 관리자 화면 |
| 정체 예보(특일·날씨·행사·운행알림) | Vercel에 백엔드 상시 배포 (데모는 FE fallback) |
| 로그인·즐겨찾기(최대 5, 출발시각 포함) | — |

## 3. 벤치마킹 → 개선점 → 차별점

발표용 **대표 3개**: 지하철종결자 · 카카오맵 · 네이버지도  
(참고: 또타/사이버스테이션 — 노선도·열차정보 강점, 혼잡 예측·경로 비교는 약함)

### 3.1 장·단점 (사용성·기능 중심)

| 서비스 | 장점 | 단점 (디자인 제외) |
|--------|------|-------------------|
| **지하철종결자** | 실시간·통계 혼잡, 칸별 색 단계, 역↔역 길안내 | 혼잡 확인까지 **화면 이동이 많음**(노선도→역→역정보→혼잡). 경로 안내와 혼잡이 **분리**되어 첫 결과에서 바로 비교하기 어려움 |
| **카카오맵** | 길찾기에서 열차 도착·혼잡·량별 시각화 일부 제공 | 혼잡이 **현재 열차** 중심. **미래 출발 시각 기준 경로 간 쾌적 비교**·역사 혼잡 통합은 약함. 노선 커버리지가 서비스마다 다름 |
| **네이버지도** | 대중교통 경로·시간 정보 익숙 | **열차 혼잡도 부재**. 혼잡 회피 의사결정에 바로 쓰기 어려움 |

### 3.2 도출한 개선·차별점 (목표에 연결)

| 카테고리 | 개선점 | 여유로 반영 |
|----------|--------|-------------|
| 기능 | 경로 결과에서 **최단 vs 쾌적**을 같은 목록에서 비교 | 경로 카드 뱃지·랭킹 |
| 기능 | **역사 혼잡**과 **열차(편성) 혼잡**을 구분해 보여 줌 | 결과/상세 스트립·열차 리스트 (칸별은 제외) |
| 서비스 | 출발 **시각 기준 예측**으로 출근 전 계획 | 시간 선택 + 슬라이더(검색 시각 근처) |
| 서비스 | 날씨·특일·행사·운행알림을 **정체 예보**로 | 홈 캐러셀 (API 연동 시) |
| 기술 | 칸별은 과거 데이터·모델 부담 → **1차 범위에서 제외** | 열차 단위 혼잡만 |
| UX | 혼잡 확인까지 탭 수를 줄임 | 검색 → 결과 카드에 혼잡 요약 → 상세 |

## 4. 타겟 · 페르소나

### 4.1 타겟

1. 출퇴근으로 지하철을 **매일** 쓰는 직장인  
2. 등하교·시험기간 이동이 많은 대학생  
3. 주말·약속 등 **시간대 선택 여지**가 있는 일반 시민  

(관광객 전용·외국어·전국 광역은 1차 목표 밖)

### 4.2 페르소나 3명

#### P1. 김서준 (32) — 출퇴근 직장인

| 항목 | 내용 |
|------|------|
| 거주지 | 서울 관악 / 직장 종로 |
| 직업 | IT 사무직 |
| 디바이스 | iPhone, 출퇴근에 지도앱 상시 |
| 유사 서비스 태도 | 카카오맵으로 최단만 보고, 혼잡은 역에 가서야 체감 |
| 목적 | 출근 전 **덜 붐비는 환승·출발 시각**을 고르고 싶음 |
| 니즈 | “5분 더 걸려도 서 있지 않는 길”을 **경로 목록에서 바로** 보고 싶음 |

#### P2. 이하은 (22) — 대학생

| 항목 | 내용 |
|------|------|
| 거주지 | 서울 마포 / 학교 근처 환승 많음 |
| 직업 | 대학생 |
| 디바이스 | Android |
| 유사 서비스 태도 | 종결자 칸별은 신기하지만 **수업 전엔 조작이 번거로움** |
| 목적 | 시험기간·행사일 **역이 막히는지** 미리 알고 싶음 |
| 니즈 | 홈에서 **오늘의 정체 예보**와 빠른 검색 |

#### P3. 박민재 (28) — 주말·약속 이동

| 항목 | 내용 |
|------|------|
| 거주지 | 서울 송파 |
| 직업 | 프리랜서 |
| 디바이스 | iPhone |
| 유사 서비스 태도 | 네이버 길찾기는 쓰지만 혼잡 정보가 없어 **도착 후 후회** |
| 목적 | 친구 약속 전 **덜 붐비는 시간·경로** 선택 |
| 니즈 | 즐겨찾기(출발 시각 포함)로 자주 쓰는 OD를 다시 조회 |

→ 세 페르소나 모두 **“출발 전, 경로 단위로 혼잡을 비교”** 라는 최초 목표에서 벗어나지 않음.

## 6. 데이터·기술 한눈에

- **경로**: ODsay `searchPubTransPathT` (실패/데모 시 fixture·로컬 그래프)
- **혼잡 예측**: LightGBM (역사 혼잡률·등급), 피처에 요일·특일·날씨·행사 등
- **예보**: 특일(천문연) · 기상청 · SPATIC/SMPA 행사 CSV · 서울교통공사 ntce
- **회원 DB (운영)**: Supabase **PostgreSQL** — `auth.users`, `public.favorite_routes` (RLS)
- **회원 DB (fallback)**: SQLite `users`, `favorite_routes` (Supabase env 없을 때)
- **배포**: GitHub Actions → Vercel (FE) · Render Docker (FastAPI, `render.yaml`)

상세 버전표: `기술내역서_요약.md`
